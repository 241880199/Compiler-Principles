## 3. 架构与数据流

### 3.1 数据流

```
源码 ──►[lexical.l]──►[syntax.y]──► AST
                                      │
                          ┌───────────┴───────────┐
                    有词法/语法错              无词法/语法错
                          │                       │
                   打印 A/B 错误          [semantic.c] 遍历 AST
                                                  │
                                          有语义错？──是──► 打印 Error type N
                                                  │
                                                  否──► 不输出任何内容
```

要求书保证输入不含词法/语法错误（选做专项测试除外），所以主路径是右边一支。左边一支保留是为了不破坏实验一已验证的行为。

### 3.2 为什么在 AST 上遍历（原文依据）

实验二指导书：

> "我们更推荐的做法是，**Bison 代码只用于构造语法树**，而把和语义分析相关的代码都放到一个**单独的文件**中去。"

实验一指导书第 25 页（**这条是我第一轮漏掉的关键证据**）：

> "要注意：**在实验二中我们还会在这棵语法树上进行一些其它的操作**，所以现在的数据结构设计会对后面的语义分析产生一定的影响。"

即"建树 → 遍历"是课件预期的做法，且实验一的 `Node` 结构就是为它准备的。因此**不在 Bison 里插语义动作**——那样语义代码会依赖 LR 的归约时机，还要把属性硬塞成综合属性（除 `Exp` 需要继承"期望类型"外本可避免）。

### 3.4 `NodeType` 枚举：非终结符级 + 子结点形态判别

**问题**：实验一的 `Node` 只有 `name` 字符串。语义分析要按结点种类分派，靠 `strcmp(n->name, "ExtDef")` 一路比下去，几十处字符串散在代码里、拼错了编译器不吭声 —— 正是实验一反复吃亏的"静默失效"。

**方案**：给 `Node` 加 `NodeType type` 字段（21 个非终结符值），但**枚举值不由调用方传**，而是 `newNode` 内部拿 `name` 查一张静态表填上。

**取舍（明确记录）**：

- **好处**：`syntax.y` 的 70 处 `newNode` 调用点**一行都不用动**。那里有实验一精心写就的错误恢复注释与冲突推演（`Def : error` 为什么不能带同步符、`Exp : error RB` 为什么有害），保持原样、diff 极小、复审成本低。
- **代价**：枚举只到非终结符级，所以**同一非终结符的不同产生式形态要靠子结点结构判别**。例如 `ExtDef` 有四种形态，由一个集中的辅助函数区分：

```c
/* ExtDef 的形态由子结点结构区分。四种产生式见 §9.1。 */
static ExtDefKind extdefKind(const Node *n) {
    if (n->nchild == 2)
        return (n->child[0]->type == NT_SPECIFIER) ? ED_STRUCT_ONLY : ED_ERROR;
    return (n->child[1]->type == NT_FUNDEC)
             ? (n->child[2]->type == NT_COMPST ? ED_FUNC : ED_PROTO)
             : ED_GLOBAL_VAR;
}
```

  这类辅助函数集中在 `semantic.c` 顶部，**每个非终结符最多一个**，不在逻辑里散开。
- **查不到名字就 `abort()`**：加了新文法规则却忘了同步枚举表时**大声报错**，不静默。

**若将来发现形态判别过于别扭**，另一条路是改成产生式级枚举并让 `syntax.y` 传值（70 处机械改动）。那是一次局部重构，不影响其它模块。

## 4. 数据结构

### 4.1 `Node` 的扩展

```c
typedef enum { /* 21 个非终结符 */ } NodeType;

typedef struct Node {
    NodeKind      kind;    /* 实验一已有：终结符 / 非终结符 */
    NodeType      type;    /* 实验二新增：非终结符种类（终结符为 NT_NONE） */
    const char   *name;
    int           line;
    const char   *lexeme;
    int           nchild;
    struct Node **child;
} Node;
```

行号语义不变（`nodeLine()` = 子树第一个词法单元的行号，实验一已实现且有单测）。

### 4.2 `Type` / `FieldList`

沿用指导书给的结构，**加三处**：

```c
typedef struct Type_ *Type;
typedef struct FieldList_ *FieldList;

struct Type_ {
    enum { BASIC, ARRAY, STRUCTURE, UNKNOWN } kind;
    union {
        int basic;                                  /* BASIC：BT_INT / BT_FLOAT */
        struct { Type elem; int size; } array;      /* ARRAY */
        struct { char *name; FieldList fields; } structure;   /* STRUCTURE */
    } u;
};

struct FieldList_ {
    char     *name;    /* 域名 */
    Type      type;    /* 域的类型 */
    Node     *node;    /* 实验二新增：该域定义处的 AST 结点，用于报错误 15 的行号 */
    FieldList tail;
};
```

三处新增及其理由：

1. **`UNKNOWN` 种**：毒化机制（§5.3）需要它。
2. **`structure.name`**：名等价要靠它区分不同结构体；**匿名结构体**也要有一个独有的隐藏名（要求书 note 3 明说），生成形如 `#anon_3` 的名字。
3. **`node` 反向指针**：报错误 15（域名重复）时要拿到重复域所在的行号，而 `FieldList` 本身不带行号。不带这个指针就得在检查时另传行号，把符号表污染成"知道行号"的模块。

### 4.3 符号表：十字链表

```c
typedef enum { SYM_VAR, SYM_FUNC, SYM_STRUCT } SymKind;

typedef struct SymEntry {
    char    *name;
    SymKind  kind;
    Type     type;        /* 变量：变量类型；函数：返回类型；结构体：结构体类型 */
    /* 函数专用 */
    Type    *params;      /* 形参类型数组 */
    int      nparams;
    int      defined;     /* 函数是否已有定义（错误 18） */
    int      declLine;    /* 首次声明/定义所在行（错误 18 的行号） */
    int      depth;       /* 所在作用域深度 */
    /* 十字链表的两条链 */
    struct SymEntry *scopeNext;   /* 同一作用域 */
    struct SymEntry *hashNext;    /* 同一散列槽 */
} SymEntry;
```

**为什么是散列 + 每层作用域链表**（指导书图 1 的十字链表）：

- 指导书给了两种风格。**Functional Style**（每进一层建一张表）配散列表会白占 `d`（最大嵌套深度）张表的空间；**Imperative Style**（单表 + 退层时删除）配"每层一条链表"正好解决删除问题。
- 它同时是课件图示的做法，报告里好写。

**查表**：走散列槽的链（链上按插入顺序 = 深度递增），返回**第一个 `depth ≤ 当前深度`** 的项。因为链头是最新插入（最深）的，所以第一个满足条件的就是最内层的定义 —— 这正是 2.2 要的遮蔽语义。

**这个选择不是那九条风险决策之一**：符号表的**接口**（`scopeEnter`/`scopeExit`/`symEnter`/`symLookup`）与它的数据结构无关，换成"每层一条链表 + 线性查找"接口完全不变。所以它是藏在窄接口后面的内部细节，可以随时改而不影响任何调用方。

**散列函数**用指导书给的 P.J. Weinberger 版本。

## 5. 类型系统

### 5.1 类型构造

`Specifier` 提供基类型，`VarDec` 在其上叠加数组维度。

**⚠️ 数组维度顺序是一个真实的实现陷阱。** `int a[10][2]` 的 `VarDec` 树是左递归的：

```
VarDec( a[10][2] ) = VarDec( VarDec( a ) LB 10 RB ) LB 2 RB
```

即**最外层的结点带的是最后一个方括号**。而 C 语义要求第一个方括号是最外维：`a` 是"10 个 `int[2]`"。所以类型必须**从右往左折叠**：

```c
/* 沿 child[0] 下行收集方括号：得到的是 从最内层到最外层 的顺序（即 [2],[10]） */
/* 再从左往右折叠，恰好得到 array(10, array(2, int)) —— 正确 */
Type t = base;
for (i = 0; i < ndims; i++) t = typeArray(t, dims[i]);
```

写成"从最外层收集、再从左折叠"就会得到 `array(2, array(10, int))`——**维度顺序反了**。

> **这个 bug 在本实验里没有任何症状，值得单独记录。** 因为 §1.4 的数组等价规则**忽略长度**，只比基类型与维数：把 `a[10][2]` 建成 `array(2, array(10, int))` 之后，
> - `a[0]` 的类型是错的，但与任何同维数组比较仍然"相等"（长度不参与判等）；
> - 维数没变，所以错误 10（对非数组用 `[]`）的触发条件也不变；
> - 错误 12 只看下标类型，与数组类型无关。
>
> 结论：**17 种检查一条都发现不了它**，端到端用例全是绿的。所以它必须靠 `type.c` 的**单元测试**钉住（§11.3），而不是靠端到端用例。这正是 §3.3 把 `type` 做成纯模块的价值所在。

### 5.2 类型等价

#### 5.2.1 统一入口

```c
/* 返回 1 表示"等价"。UNKNOWN 与任何类型等价 —— 见 §5.3。 */
int typeEqual(Type a, Type b);
```

#### 5.2.2 数组与基本类型

- `BASIC`：种类相同即等价。
- `ARRAY`：**维数相同**（沿 `elem` 链下行直到非 `ARRAY`，比较深度）**且基类型等价**。**长度不参与判等**（§1.4）。

#### 5.2.3 结构体：名等价 vs 结构等价

**名等价**（假设 5 的默认）：`a == b` 指针相等即可。之所以能这么简单，是因为**结构体类型只在定义处创建一次**，所有 `struct A` 的引用都解析到符号表里同一个 `Type` 指针（§6.3）。匿名结构体各自有一个独有的隐藏名（要求书 note 3），所以两个匿名结构体天然不等价。

**结构等价**（选做 2.3）：忽略域名，**按位置**逐个比较域的**类型**，域的**数量**必须相同：

```c
static int fieldsEqual(FieldList a, FieldList b) {
    while (a && b) {
        if (!typeEqual(a->type, b->type)) return 0;   /* 比类型，不比 name */
        a = a->tail; b = b->tail;
    }
    return a == NULL && b == NULL;                    /* 数量必须相同 */
}
```

**"不展开数组"的含义**：数组域的 `typeEqual` 走的是 §5.2.2 的 ARRAY 分支，即把整个数组当作 `(基类型, 维数)` 一个单位比较，**不会把数组摊成它的元素再逐个比**。

这一步是要求书 2.3 那个例子的全部意义所在。把数组展开会得到错误的答案：

```
A = struct A { int a; struct { float f; int i; } b[10]; }
    展开后类型序列: int, [float,int]×10        → 21 项
B = struct B { struct { int i; float f; } b[10]; int b; }
    展开后类型序列: [int,float]×10, int        → 21 项
    逐位比较：int==int, float==float, … 完全相同
```

展开后 A 与 B **逐位相同**，会被误判为等价——而要求书明说它们不等价。按"不展开"的规则：A 的第 0 个域是 `int`，B 的第 0 个域是 `array`，种类就不同，立刻判出不等价。✓

> 这条同时是"结构等价忽略域名"的独立佐证：那对**等价**的例子里域名是 `x,y` 对 `y,z`，不同。

**递归终止**：C-- 不允许结构体包含自身（`struct A { struct A x; }` 在字段处理时 `A` 尚未入表，会先报错误 17），所以 `typeEqual` 的递归**不会成环**。这一点要写进注释，否则下一个读者会怀疑它。

### 5.3 `UNKNOWN` 与毒化

要求书说连锁反应时"我们只会去考察你的程序是否报告了**较本质**的那个错误"。最典型的连锁是：变量未定义 → 类型未知 → 所有含它的表达式都"类型不匹配"。

**机制**：名字查不到时，把该表达式的类型记为 `UNKNOWN` 单例，并报错误 1 或 2。此后：

- `typeEqual(UNKNOWN, 任何)` 返回 **1**（等价）；
- 各检查点遇到 `UNKNOWN` 操作数一律**静默**（视作"无法判定，不报"）；
- 含 `UNKNOWN` 的表达式，其类型继续传播 `UNKNOWN`。

效果：`j = i + 1;`（`j` 未定义）只报一条错误 1，不再附带错误 7。

## 6. 作用域模型（选做 2.2）

### 6.1 层次

- **全局作用域**（深度 0）：所有 `ExtDef` 引入的全局变量、函数、结构体名。
- **函数作用域**：进入一个函数定义时压入。
- **语句块作用域**：每个 `CompSt` 压入一层（函数体的 `CompSt` 除外，见下）。

### 6.2 形参与函数体**同作用域**（暂定取舍第 3 条）

`ExtDef → Specifier FunDec CompSt` 的处理：

```
scopeEnter()               ← 函数作用域
遍历 FunDec 插入形参
遍历 CompSt 的**子结点**（不再次 scopeEnter）
scopeExit()
```

后果：`int f(int i) { int i; }` 报**错误 3**（与 C 一致）。理由与开关位置见 §8。

### 6.3 结构体名的注册层级（暂定取舍第 4 条）

结构体定义**注册在当前作用域**，不开特例。

注意 C-- 里**不存在"只定义结构体不定义变量"的局部语句**：`Def → Specifier DecList SEMI` 要求 `DecList` 非空，所以函数体内的结构体定义必然形如 `struct A {...} v;`，注册在当前作用域是自洽的。

**名的解析**：`StructSpecifier → STRUCT Tag` 时查符号表。查到的 `Type` 指针被所有引用共享 —— 这是 §5.2.3 名等价能退化成指针比较的原因。

### 6.4 名字空间的冲突规则（暂定取舍第 1 条）

变量、函数、结构体**共用一个名字空间**（单一 `SymEntry` 链）。填入时按已有项与新项的**种类组合**决定错误码，规则收敛在 `symtab.c` 的一张小表里 —— 见 §8 第 1 条。

### 7.1 两个候选同时成立时的固定检查顺序

这几处顺序不写下来就会变成"碰巧"，必须显式固定：

| 表达式 | 顺序 | 依据 |
|---|---|---|
| `Exp ASSIGNOP Exp` | **先 6（左值性）后 5（类型等价）** | 左值性只看左子结点的**形态**，不需要类型信息，天然在先 |
| `Exp LB Exp RB` | **先 10（基类型是否数组）后 12（下标是否整数）** | 要求书样例 10 的 `i[0];`（`i` 是 int、下标是 int）只该出一条，所以 10 必须先检、并**短路**后续检查 |
| `Exp DOT ID` | **先 13（基类型是否结构体）后 14（域是否存在）** | 不是结构体就无从查域 |
| 调用 `ID LP … RP` | **先 11（是不是函数）后 2（是否定义）后 9（实参匹配）** | 命中一条即短路；样例 11 的 `i(10)`（`i` 是变量）只该出 11 |

**短路后的类型**：被短路的分支一律返回 `UNKNOWN`，从而抑制下游连锁（§5.3）。这条例外——若基类型是 `UNKNOWN`（变量本身未定义），**10/12/13/14 全部静默**，只留上游那条错误 1。

## 9. 文法改动

### 9.1 新增产生式（选做 2.1）

附录 A 的 `ExtDef` 只有三条产生式，没有函数声明。新增一条：

```
ExtDef → Specifier FunDec SEMI      /* 函数声明（原型），选做 2.1 */
```

**为什么不与 `Specifier ExtDecList SEMI` 冲突**：在 `Specifier` 之后看到 `ID` 时，状态里同时有 `VarDec: ID •` 与 `FunDec: ID • LP …`。前瞻为 `SEMI`／`COMMA`／`LB` 时归约为 `VarDec`，前瞻为 `LP` 时移进 —— `FunDec` 的两条产生式都以 `ID LP` 开头，**LALR(1) 足够**，不产生新的移进/归约冲突。

**不支持的写法**：省略参数名的声明（`int foo(int, float)`）。要求书明说"我们并不要求支持"，故 `ParamDec → Specifier VarDec` 保持不变。

**要求书要求"改动应该以不影响其它错误类型的检查为原则"** —— 这条产生式只新增可接受的输入，不改变任何既有输入的分析结果。

### 9.2 冲突数哨兵必须重新标定

实验一的 `scripts/run_tests.sh` 断言 `syntax.output` 里**恰好 3 个冲突 state、每个都是 1 shift/reduce**，并详细记录了三处的归属（State 26/31 由 `Def : error` 引起，State 114 是悬空 else）。

**新增产生式会改变状态编号，也可能改变冲突数。** 处置：

1. 实测新值，**重新推演每一处冲突的归属**，把推演写进脚本注释（照实验一的规格：state 号、产生式项、冲突双方）。
2. 新期望值必须**实机验证**——在 Bison 3.8.2 与 3.0.4 下各测一次（实验一验证 3.0.4 的做法：从 Ubuntu bionic 归档取 `bison_3.0.4.dfsg-1build1_amd64.deb` 解包，配 `BISON_PKGDATADIR`）。
3. **哨兵语义不变**：冲突数一变就报警，不区分"变好"还是"变坏"。这条断言不可省——实验一实测过，有无 `%left LB DOT` 的 LR 动作表**逐字节完全相同**，所有 `.exp` 比对都察觉不到它被误删。

### 9.3 实验一 30 个用例必须全绿

`int a;`、`int f(){}` 等既有输入的语法树**一个字节都不能变**。新增产生式只扩展可接受的语言，这一点要在实施时用实验一的 30 个用例实测确认（§11.2）。

## 10. 输出与编排

### 10.1 输出格式

```
Error type [错误类型] at Line [行号]: [说明文字].
```

- 无错时**不输出任何内容**（实验一是打印语法树，**这条必须改掉**）。
- 错误信息输出到 **stdout**（要求书明确，判分脚本读 stdout）。
- 说明文字内容不限；**错误类型与行号是唯一评分标准**，必须正确。
- 退出码：正常分析完毕返回 0（无论有无语义错误）；仅缺文件名参数或文件打不开返回 1。**沿用实验一的约定**（实验一实测助教未规定退出码，且实验一已按此通过）。

### 10.2 `report.c` 的改动

实验一的 `reportError(char type, int line, const char *msg)` 打印 `%c`（A/B）。实验二需要数字。

**做法**：新增数字类型的入口，**实验一的 A/B 路径原样保留**，两条路径各自的同行去重互不干扰：

```c
void reportError(char type, int line, const char *msg);   /* 实验一：A/B，原样不动 */
void reportSemanticError(int code, int line, const char *msg);  /* 实验二：1-19 */
```

**为什么分开而不是合并**：实验一那段的"抑制同一行上跟在本条 type A 之后的 type B"是一段有已知代价的近似逻辑（`report.c` 里有详细注释），实验一有 30 个字节级用例依赖它的行为。**合并两条路径的风险是把实验一已验证的行为改坏**，而实验二的输入按约定不含 A/B 错误，两条路径在评测中根本不会相遇。分开是零风险的。

`reportSemanticError` 维护自己的**已打印行号集合**（`semPrintedLines[]` + `semPrintedCount`，容量 128；线性查找足够，语义错误一共 19 种、打印条数是个位数）——**任何打印过的行**再次报出时直接返回 0（暂定取舍第 9 条 + 要求书"每行最多只有一个错误"）。去重仍收敛在 `report.c` 的**这一处**（§8 第 9 条的"开关位置"）。

> **为什么是集合而不是"最近一次打印的行号"（2026-09-22 评审修正）。** 判据是无条件的：一条**打印过**的行，此后**任何时刻**再报都必须被抑制，与相邻与否无关。只记"上一个行号"只能挡住**连续**的同行错误 —— 行号非单调时（L → M → L，M > L）第 L 行会被打印第二次，直接违反要求书。
>
> **可达性是真实的，不是理论构造**：§7 的检查顺序表刻意**不**在错误 6 与错误 5 之间短路 `Exp ASSIGNOP Exp` —— 先在左子结点的行报 6，再分析右操作数（可以报在**更靠后**的行），最后回到赋值语句的行报 5。`UNKNOWN` 毒化只在中间那条错误返回 `UNKNOWN` 时才救场，而**错误 9 返回的是函数返回类型而非 `UNKNOWN`**，所以 `(x) = f(1,2)` 这类（`x` 为 float、`f` 返回 int、实参不匹配）能真的走出 L → M → L。
>
> **判别用例**：`Test/unit/test_report.c` 中 `4 → 9 → 4` 那一条（旧近似红、新集合绿，配对实验见 Task 5 修正报告）。原计划把收敛推给 Task 7 的 `dec09_sameline.cmm`，那条路子**已作废** —— 该用例是**相邻**同行错误，对非单调顺序零判别力。

| 文件 | 内容 | 检验什么 |
|---|---|---|
| `NN.exp` | 我们程序的完整输出，逐字节 | **我们的文本稳定**（防回归） |
| `NN.pairs` | 官方参考输出的 `(错误类型, 行号)` 序列 | **评分字段正确**（防判分失分） |

`run_tests.sh` 两条都查。这样"我们改了说明文字"与"我们的错误类型/行号错了"能被分开暴露——前者只动 `.exp`，后者必须动代码。合并成一条就会重演实验一的教训：**判据混在一起，改坏了一条也不知道是哪条。**

### 11.4 `type.c` 的单元测试（必须）

§5.1 的数组维度顺序错误**没有任何端到端症状**（长度不参与判等、维数不变、错误 12 只看下标类型）。所以它只能靠单元测试钉住：

- `int a[10][2]` 的类型必须是 `array(10, array(2, int))`（**查具体的 size 值**，不能只查维数）
- `int a[10][2]` 与 `int b[5][3]` 等价（长度忽略）
- `int a[10]` 与 `int b[10][2]` 不等价（维数不同）
- 结构等价：`{int x; float y;}` ≡ `{int y; float z;}`（忽略域名）
- 结构不等价：§5.2.3 那对 A/B（数组不展开）
- 名等价：两个匿名结构体不等价

### 11.5 判别力验证（变异测试）

沿用实验一的做法：每个关键判据都要证明"把它改坏，有用例会红"。

至少覆盖：
1. 名等价 ↔ 结构等价 互换 → 选做的样例 5/6 必须变红；
2. 去掉 `%left LB DOT` → **只有冲突数哨兵**能发现（实验一实测 LR 动作表逐字节不变）；
3. 数组等价改成比较长度 → `int a[10][2]` 与 `int b[5][3]` 的用例变红；
4. 结构等价改成比较域名 → 2.3 的等价样例变红；
5. 结构等价改成展开数组 → 2.3 的不等价样例变红（**这条是 §5.2.3 那个发现的直接验证**）；
6. 去掉 `UNKNOWN` 毒化 → 连锁报错的用例变红；
7. 去掉数组维度折叠 → **只有 §11.4 的单测能发现**（端到端全绿）。

### 11.6 继承实验一的脚本断言

`run_tests.sh` 已有一批防"静默通过"的断言，**全部继承并适配**：stderr 必须为空（与 stdout 分别重定向）、parser 退出码必须为 0、缺 `.exp` 判 FAIL 而非 SKIP、`pass>0` 守卫、冲突数锚定模式匹配（`[Ss]tate` 兼容 Bison 3.0.4）、显式声明未纳入范围的 `.cmm`。

新增：**§11.3 的 `(type,line)` 序列断言**与**§8 的九条决策用例必须存在**（缺一个判 FAIL——否则"决策用例"会因漏建而静默消失，与实验一 `crlf.cmm` 那次同类）。

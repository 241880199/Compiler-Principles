# C-- 实验一实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现一个 Flex + Bison + C 的 C-- 语言词法/语法分析器，检出词法错误（type A）与语法错误（type B），无错时按先序打印语法树。

**Architecture:** `YYSTYPE` 直接是 `Node *`，终结符与非终结符同构，打印器只需一份遍历代码。行号与 ε 判定共用同一个 `nodeLine()` 递归函数：返回子树中第一个词法单元的行号，返回 0 即表示该结点产生了 ε。词法层用起始条件处理注释，用"最长匹配抢优先权 + action 内校验"检出非法数字。

**Tech Stack:** GNU Flex 2.6.4、GNU Bison（3.0.4 / 3.8.2 通用写法）、GCC、GNU Make、bash

**设计文档：** `docs/superpowers/specs/2026-09-20-cmm-lab1-design.md`（实现时遇到歧义以此为准）

## Global Constraints

- 编译环境：WSL2 `Ubuntu-22.04`，通过 `wsl.exe -d Ubuntu-22.04 -u root -- bash <script>` 执行。Windows 侧**没有** gcc/flex/bison，一切编译运行必须在 WSL 内。
- **传给 WSL 的命令里，shell 变量必须转义**：`$?`、`$f`、`$n` 等在抵达 WSL 之前就会被某一层展开，**静默产生错误结果**。实测（Git Bash → WSL）：
  - `bash -lc 'false; echo "status=$?"'` → 打印 `status=0`（**假**，应为 1）
  - `bash -lc 'false; echo "status=\$?"'` → 打印 `status=1`（正确）
  - `bash -lc 'for f in a b; do echo "got:$f"; done'` → 打印两行 `got:`（**变量被吞成空**）
  凡命令中含 shell 变量，一律写 `\$?`、`\$f`；或避开变量，改用 `&&` / `||` 串联，或把逻辑写成脚本文件再执行。**用 `$?` 取证退出码时尤其危险——会得出与事实相反的结论。**
- 工具版本：gcc 11.4.0 / flex 2.6.4 / bison 3.8.2。代码须与评分环境（Ubuntu 20.04 / GCC 7.5.0 / Flex 2.6.4 / Bison 3.0.4）兼容。
- **禁止**使用 `%define parse.error detailed`（Bison 3.0.4 不支持）。**禁止**使用 `&:` 分组目标（GNU Make 4.2 不支持）。
- **禁止**使用 glib 等第三方库。只用 C99 标准库 + flex/bison 自身。
- 构建命令**不加 `-ly`**（本机无 `liby`，且自定义了 `main` 与 `yyerror`）。保留 `-lfl`。
- 所有文本文件必须 LF 行尾（`.gitattributes` 已强制）。词法分析器**还须主动容忍 `\r`**。
- 错误输出格式固定为 `Error type [A|B] at Line [n]: [说明].`，句末的 `.` 由 `reportError` 统一追加。
- 有错时**只输出错误信息，绝不输出语法树**。
- 每条错误单独占一行；输入文件的同一行保证不出现多个错误。
- 测试文件的期望输出**必须手工推导**，不得从程序实际输出反填。

int main(void) {
    Node *t;

    /* 树 1：Program → ExtDefList → ε
       整棵子树不含词法单元 → 产生了 ε → 不应打印任何内容 */
    printTree(newNode("Program", 1, newNode("ExtDefList", 0)));

    printf("===== 分隔 =====\n");

    /* 树 2：行号全部由最左词素推导；覆盖 有词素/无词素 两类词法单元 */
    t = newNode("Program", 1,

                    newNode("FunDec", 3,
                        newToken("ID", 1, "inc"),
                        newToken("LP", 1, NULL),
                        newToken("RP", 1, NULL)),
                    newToken("SEMI", 1, NULL))));
    printTree(t);

    printf("===== 分隔 =====\n");

    /* 树 3：第一个子结点是 ε 时不占行、不占位，行号应取自其后第一个词素 */
    t = newNode("DefList", 2,
            newNode("DefList", 0),
            newNode("Def", 2,
                newNode("Specifier", 1, newToken("TYPE", 3, "float")),
                newToken("SEMI", 3, NULL)));
    printTree(t);

    printf("===== 分隔 =====\n");

    /* 树 4：数值词素 */
    t = newNode("Exp", 2,
            newToken("INT", 4, "83"),
            newToken("FLOAT", 4, "0.000105"));
    printTree(t);

    printf("===== 分隔 =====\n");

    /* 树 5：同一子树内各词素的行号**互不相同** —— 钉住"取第一个词素的行号"
       若实现取最后一个（或最大）行号，这里会打印出 Def (4) 而非 Def (1) */

            newNode("Specifier", 1, newToken("TYPE", 1, "int")),
            newNode("DecList", 1,

- [ ] **Step 5: 实现 `src/tree.c`**

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <stdarg.h>
#include "tree.h"

static void *xmalloc(size_t n) {
    void *p = malloc(n);
    if (!p) { fprintf(stderr, "out of memory\n"); exit(1); }
    return p;
}

static char *xstrdup(const char *s) {
    if (!s) return NULL;
    char *p = xmalloc(strlen(s) + 1);
    strcpy(p, s);
    return p;
}

Node *newToken(const char *name, int line, const char *lexeme) {
    Node *n = xmalloc(sizeof(Node));
    n->kind   = NODE_TOKEN;
    n->name   = xstrdup(name);
    n->line   = line;
    n->lexeme = xstrdup(lexeme);
    n->nchild = 0;
    n->child  = NULL;
    return n;
}

Node *newNode(const char *name, int nchild, ...) {
    Node *n = xmalloc(sizeof(Node));
    va_list ap;
    int i;

    n->kind   = NODE_GRAMMAR;
    n->name   = xstrdup(name);
    n->line   = 0;          /* 行号一律由 nodeLine() 推导，不在此处指定 */
    n->lexeme = NULL;
    n->nchild = nchild;
    n->child  = nchild ? xmalloc(sizeof(Node *) * (size_t)nchild) : NULL;

    va_start(ap, nchild);
    for (i = 0; i < nchild; i++) n->child[i] = va_arg(ap, Node *);
    va_end(ap);

    return n;
}

/* 子树中第一个词法单元的行号；子树不含词法单元时返回 0。
 * 返回 0 同时就是"该结点产生了 ε"的判定 —— 见设计文档 §4.1。 */
static int nodeLine(const Node *n) {
    int i;
    if (n->kind == NODE_TOKEN) return n->line;
    for (i = 0; i < n->nchild; i++) {
        int l = nodeLine(n->child[i]);
        if (l > 0) return l;
    }
    return 0;
}

static void printNode(const Node *n, int depth) {
    int i, line;

    if (n->kind == NODE_GRAMMAR) {
        line = nodeLine(n);
        if (line == 0) return;          /* 产生了 ε，不打印、不占位 */
    } else {
        line = n->line;
    }

    for (i = 0; i < depth; i++) printf("  ");

    if (n->kind == NODE_TOKEN) {
        if (n->lexeme) printf("%s: %s\n", n->name, n->lexeme);
        else           printf("%s\n", n->name);
    } else {
        printf("%s (%d)\n", n->name, line);
    }

    for (i = 0; i < n->nchild; i++) printNode(n->child[i], depth + 1);
}

void printTree(const Node *root) { printNode(root, 0); }
```

- [ ] **Step 1: 写 `scripts/run_tests.sh`**

```bash
#!/usr/bin/env bash
# 遍历 Test/ 下全部 .cmm，与同名 .exp 逐字节比对
set -u
cd "$(dirname "$0")/.."

if [ ! -x ./parser ]; then
    echo "错误：未找到 ./parser，请先运行 make" >&2
    exit 1
fi

pass=0
fail=0
tmp=$(mktemp)
trap 'rm -f "$tmp"' EXIT

for cmm in Test/sample/*.cmm Test/err/*.cmm; do
    [ -e "$cmm" ] || continue
    exp="${cmm%.cmm}.exp"
    if [ ! -f "$exp" ]; then
        echo "SKIP  $cmm  （无同名 .exp）"
        continue
    fi
    ./parser "$cmm" > "$tmp" 2>&1
    if diff -q "$exp" "$tmp" > /dev/null; then
        pass=$((pass + 1))
    else
        fail=$((fail + 1))
        echo "FAIL  $cmm"
        diff -u "$exp" "$tmp" | sed 's/^/      /' | head -30
    fi
done

# ── 冲突数断言 ────────────────────────────────────────────────
# 唯一允许的冲突是悬空 else（设计文档 §6.2.1 / §6.2.2）。
# 这条断言不可省：实测有无 %left LB DOT 的 LR 动作表**完全相同**，
# 所有 .exp 比对都察觉不到它被误删，只有这个计数能发现。
if [ -f syntax.output ]; then
    n=$(grep -c "conflicts:" syntax.output)
    if [ "$n" -ne 1 ]; then
        echo "FAIL  期望恰好 1 个冲突 state（悬空 else），实测 $n 个"
        grep -n "conflicts:" syntax.output | sed 's/^/      /'
        fail=$((fail + 1))
    elif ! grep -q "conflicts: 1 shift/reduce" syntax.output; then
        echo "FAIL  唯一的冲突 state 不是「1 shift/reduce」"
        grep -n "conflicts:" syntax.output | sed 's/^/      /'
        fail=$((fail + 1))
    fi
else
    echo "FAIL  未找到 syntax.output —— 冲突数断言无法执行"
    echo "      （它由 bison -v 生成。脚本开头已确认 ./parser 存在，而 test 目标依赖"
    echo "        parser，故该文件本应存在；缺失说明构建链被绕过）"
    fail=$((fail + 1))
fi

echo "----------------------------------------"
echo "通过 $pass 个，失败 $fail 个"
[ "$fail" -eq 0 ]
```

> 注意：上面这些 `$cmm`、`$exp`、`$pass` 等变量**写在脚本文件里是安全的** ——
> 转义陷阱只影响**通过 `wsl.exe ... bash -lc '...'` 内联传递**的命令。脚本落盘后由
> WSL 内的 bash 执行，变量按正常规则展开。
>
> **冲突数断言缺失时判 FAIL 而非 SKIP。** 脚本开头已经确认 `./parser` 存在，而 `test`
> 目标依赖 `parser`（其构建必经 `bison -v`），所以 `syntax.output` **本应存在**。缺失
> 意味着构建链被绕过 —— 那正是断言最该警觉的情形，判 SKIP 等于在需要它的时候关掉它。
>
> ⚠️ **不要改用 `%expect 1` 来达成同一目的。** 它看起来更干净（让 bison 自己把关），
> 但风险不对称：一旦评分环境的 **Bison 3.0.4** 与我们实测的 3.8.2 在冲突计数上有
> 任何差异，`%expect` 会把一个**警告**升级成**构建失败** —— 而要求书 2.1.5 明确写着
> "无法顺利编译将导致助教无法对你的程序所实现的功能进行任何测试，从而丢失相应的分数"。
> 脚本级断言失败最多是自测红一条，`%expect` 失败是整个程序编译不出来。**取低风险那个。**

> **必须有三条错误，不是两条。** 恢复机制要连续成功三次，第 9 行才会被看见 ——
> 这直接检验"能报出**全部**错误"这个特性的真正保证。只有两条时，一次恢复就够，

> **为什么用语句层错误而不是定义层错误**：本计划原稿用的是「`int a` / `int b;`」这种
> **局部定义**缺分号，期望报出行 4 与行 6。**实测该期望无法达成** —— 只报行 4，
> 然后一路弹到 `ExtDef → Specifier FunDec . CompSt`，在函数末尾的 `}` 处同步，
> 行 6 再也看不到。原因是 `CompSt → LC . DefList StmtList RC` 状态的闭包里**没有**
> `error` 出口（`StmtList` 在 `DefList` **之后**，不在其闭包中）。详见设计文档 §6.3
> 的"已知限制"。
>
> 故本用例改为**语句层**错误，这是当前 `error` 产生式集合能完整恢复的情形。
>
> **行号是 5 和 7，不是 4 和 6。** 报错行号指向的是**让分析器无法继续的那个词法单元**，
> 而不是语法上"缺失"的位置：第 4 行缺的 `;` 要等到读入第 5 行的 `a`（ID）时才暴露，
> 所以报第 5 行；第 6 行同理，报第 7 行。（要求书样例 2 里 offending token 恰好与
> 缺失位置同行，故看似相同。）
>
> 两条错误的恢复路径：解析器位于 `StmtList → Stmt . StmtList` 时其闭包含
> `Stmt → . error SEMI`，故弹到该处即可移进 `error`，丢弃到本行 `;` 后归约
> `Stmt : error SEMI`，随后继续解析下一条语句。
>
> 注意第一条恢复会**吞掉第 5 行的 `a = 2;`** —— 这是设计使然，不是缺陷。

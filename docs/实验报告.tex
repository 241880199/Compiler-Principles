\section*{三、亮点 1：行号推导与 $\varepsilon$ 判定是同一件事}

语法单元的行号由结构递归推导，而不在每个 action 里赋值：

\begin{lstlisting}[language=C]
static int nodeLine(const Node *n) {        /* 子树中第一个词法单元的行号 */
    if (n->kind == NODE_TOKEN) return n->line;     /* 0 表示不含词法单元 */
    for (int i = 0; i < n->nchild; i++) { int l = nodeLine(n->child[i]);
        if (l > 0) return l; }
    return 0;
}
\end{lstlisting}

词法单元的行号由 lexer 写入一次，是唯一可信来源；语法单元的行号则是\textbf{结构的
函数}。这消除了「某个产生式忘了写行号」这\emph{一整类} bug——写产生式时根本不必
想着行号。

真正值得说的是后半句。要求书规定「该语法单元产生了 $\varepsilon$ 则无需打印」，而

\begin{center}
「产生 $\varepsilon$」$\iff$ 推不出任何词素 $\iff$ \textbf{整棵子树不含词法单元}
$\iff$ \code{nodeLine} 返回 \code{0}
\end{center}

\textbf{二者是同一件事}——所以不需要第二个标志位，$\varepsilon$ 判定是行号推导的
副产品，而不是另一段代码。一个很自然的错法是用 \code{nchild == 0} 判
$\varepsilon$：\code{Program -> ExtDefList -> $\varepsilon$} 时 \code{Program} 有
\emph{一个}子结点，会被误判为非 $\varepsilon$，于是打印出一行无关的
\code{Program (0)}——而行号 \code{0} 本身其实已经暴露了它推不出任何词素。

\section*{四、亮点 2：错误恢复的同步点设计}

要求书 2.1.3 要求报告\textbf{全部}错误，而 Bison 默认遇错即停，故须用 \code{error}
产生式给出恢复出口。最终采用四个：\code{Stmt : error SEMI}（语句层）、
\code{CompSt : error RC}（块层）、\code{ExtDef : error SEMI}（顶层，避免弹空栈
中止），以及\textbf{\code{Def : error}（定义层，不带同步符）}。

\subsection*{4.1 「带不带同步符」比「放哪一层」更重要}

\code{error} 带同步符时，Bison 会先\textbf{丢弃}词法单元直到同步符出现才归约；而
\textbf{裸 \code{error} 移进后立即归约、不丢弃任何前瞻}。这一点直接决定能报出多少错误：

{\small
\begin{tabular}{@{}llp{4.0cm}p{4.0cm}@{}}
\toprule
写法 & 冲突 state & 场景①\newline 块内定义缺分号、块继续 & 场景②\newline 缺分号紧接 \code{\}}、后有兄弟 \\
\midrule
不加 & 1 & \textbf{只报 1 条}（少报） & 报 2 条 \\
\code{| error SEMI} & 3 & 报 2 条 & \textbf{只报 1 条}（少报） \\
\code{| error RC} & 3 & \textbf{只报 1 条}（少报） & 报 2 条 \\
\textbf{\code{| error}（裸）$\to$ 采纳} & \textbf{3} & \textbf{报 2 条} & \textbf{报 2 条} \\
\bottomrule
\end{tabular}}

机理：场景② 里整份文件\textbf{一个 \code{;} 都没有}，\code{error SEMI} 只能一路
丢到 EOF，于是只报第 1 条；\code{error RC} 则把 \code{\}} 本身当同步符吃掉，块内
后续内容整段消失。裸 \code{error} 不丢任何东西，\code{\}} 仍在流里、外层结构照常
走完。\textbf{这是纯收益}：裸 \code{error} 引入的 2 个冲突与 \code{error SEMI}
\emph{完全相同}——冲突由 \code{error} 符号本身引起（\code{DefList} 可空），与后面
跟不跟同步符无关。

\subsection*{4.2 一处被实测推翻的设计}

原设计还有一条 \code{Exp : error RB}，推演看着很对：\code{a[5,3] = 1.5;} 在下标处
出错时就地恢复、正好在 \code{]} 同步。\textbf{实测加入它反而报出 3 条错误}（行 5、
行 5、行 6），直接违反要求书「同一行不出现多个错误」。用 \code{bison -t} 的调试
轨迹查明：\code{Exp LB . Exp RB} 状态的\textbf{闭包里就含}
\code{Exp -> . error RB}，所以 Bison 在下标\emph{内部}就找到出口、\textbf{停止弹
栈}；而 \code{error} 的同步符 \code{RB} \textbf{恰好就是外层 \code{[} 正在等待的
那个 \code{]}}，被内层吃掉后外层永远等不到闭合。

\textbf{教训}：设计 \code{error} 同步点，不能只看「error 之后想跟什么」，还要看
\textbf{这个出口是否已在当前状态的闭包里}——在的话 Bison 就地停下，\emph{不会}按
预期往外弹栈。（另有一处如实说明：\code{CompSt : error RC} 的判别力已被裸
\code{Def : error} 吸收，实测删掉它后冲突数与 30 个用例都不变；本轮不删，但也不
声称它仍在起作用。）

\section*{五、亮点 3：一个「任何样例都守不住」的冲突数哨兵}

文法里必须显式声明 \code{\%left LB DOT} 为最高优先级。理由是一条容易被忽略的规则：
栈上 \code{Exp PLUS Exp .} 遇前瞻 \code{LB} 时，归约得 \code{(a+b)[1]}、移进得
\code{a+(b[1])}，\textbf{两棵树都合法}——这是真实的 shift/reduce 冲突。而 Bison
只在\textbf{规则与前瞻 token 都声明了优先级}时才消解，不声明则这类冲突\emph{根本
不进入优先级判定}（实测：只声明其余运算符时 \code{Exp} 的 100 处冲突只能消掉 80
处，剩下的 20 处正是 \code{LB}/\code{DOT} 引起的）。

关键在于把这一行\textbf{删掉}会发生什么：

{\small
\begin{tabular}{@{}lll@{}}
\toprule
观察项 & 有该行 & 删掉后 \\
\midrule
冲突 state 数 & \textbf{3} & \textbf{13} \\
LR 动作表（\code{yypact}/\code{yydefact}/\code{yytable}/\code{yycheck}/\code{yystos} 等） & —— & \textbf{逐字节完全相同} \\
30 个用例的逐字节比对 & 全过 & \textbf{照样全过} \\
\bottomrule
\end{tabular}}

即：删掉它之后\textbf{程序对外行为一模一样}（显式声明优先级与 Bison 默认移进在这
里恰好得出同一张表），全部用例照过。\textbf{除了冲突计数，没有任何测试能发现它被
误删。} 于是我把「冲突数恰好 3」写成断言——三个冲突的归属逐条核实过（两处是
\code{DefList} 可空引起的「移进 \code{error}」与「按 \code{DefList} ->
$\varepsilon$ 归约」之争，一处是悬空 else）。

\textbf{「恰好 3 处冲突」不是评分项，而是本项目的哨兵}——它把一个所有样例都察觉
不到的静默退化，变成了一跑就红的断言。

\section*{六、已知限制（明知的取舍）}

\textbf{限制一：同行 type B 抑制可能吞掉一条真实错误。} 实现里有一条「同一行上跟
在本条 type A 之后报出的 type B 不打印」的抑制，理由是官方选做样例 2 / 4 的期望
输出\emph{只含 type A 行、不含 type B}。判据是按「已报告过的行号」做的\textbf{近似，
不是因果判断}，故会误伤：\code{int main() \{ int a = 1} 换行 \code{\~{} \}} 实测只
报 A，那条真实的缺分号错误被一起吞掉。边界：\textbf{符合要求书「同一行不出现多个
错误」前提的输入下，本程序仍可能少报一条同行 type B}。

\textbf{限制二：语法错误的恢复不保证覆盖到文件末尾。} 顶层与块内的出口能继续分析，
但另有一些出错点（如定义层错误其后既无 \code{;} 又无 \code{\}}）仍会中止分析、丢掉
后续的\emph{语法}错误——词法错误已由 \code{main} 中的收尾扫描保证不丢。

\textbf{其余}：不做语义分析、符号表、类型检查（属实验二）；不支持注释嵌套
（C{-}{-} 明确不支持，嵌套时在第一个 \code{*/} 处闭合，其后残留的 \code{*/} 退化为
type B——这正是要求书样例的期望行为）；只接受单个输入文件名参数；递归深度未设上限。

\textbf{一条值得单独记的教训}：未闭合注释在\emph{词法层}只报一条 type A，但端到端
时若 \code{/*} 位于一个永远无法闭合的函数体内，语法分析器会\textbf{额外}报一条
type B。这个差异最初没被发现，因为词法单测跑的是 \code{yylex()}、
\textbf{根本不经过语法分析器}。\textbf{词法层测过的行为，不等于端到端的行为；单测
覆盖了某个模块，不代表该模块在完整流水线里的表现已被覆盖。}

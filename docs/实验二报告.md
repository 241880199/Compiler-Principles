## 一、实现的功能，以及如何实现

| 功能 | 如何实现 |
|---|---|
| **19 个错误码**（必做 17 + 选做 2.1 的 18、19） | 前端仍是实验一的 Flex + Bison（文法只加了一条产生式），**语义分析完全手写**：在实验一建好的语法树上做一遍后序遍历。三个模块单向依赖 —— `semantic.c`（遍历与 19 种检查）→ `symtab.c`（符号表）→ `type.c`（类型表示与等价）。 |
| 错误 1/2 的**连锁抑制** | 名字查不到时返回 `UNKNOWN` 单例并报 1/2；`typeEqual(UNKNOWN, 任何)` 为真，各检查点遇 `UNKNOWN` 一律静默。否则 `j = i + 1;`（`j` 未定义）会附带一条类型错 —— 要求书只考察「较本质」的那条。 |
| 嵌套作用域（选做 2.2） | 符号表是散列 + 每层一条链表；查表沿链由内向外，返回**第一个 `depth ≤ 当前深度`** 的项 —— 这就是「遮蔽」。`scopeEnter`/`scopeExit` 全项目只有两处调用点（函数体、语句块），形参与函数体同层。 |
| 函数声明（选做 2.1） | 声明的形参收集与定义的走**同一条**路径，比较（返回类型, 形参数, 形参类型表）；文件末尾遍历全局链表报「声明了但从未定义」（错误 18），行号取**首次**声明处。 |
| 结构等价（选做 2.3） | 忽略域名、按位置比域的类型，域数量必须相同；数组整体作为一个（基类型, 维数）单位比较，**不展开**（为什么必须如此，见第三节）。 |
| 输出，与和实验一的关系 | 词法/语法错仍报 `A`/`B`；**完全无错时不输出任何内容**（不再打印语法树）。语义报告走 `reportSemanticError`，它维护一个**已打印过的行号集合**，重复行直接丢弃（判据无条件，不依赖「相邻」）；实验一的 A/B 路径原样保留，两条路径的去重状态互不干扰。实验一的 30 个用例改由回归驱动 `Test/regress/driver` 跑，作语法层回归网。 |

## 三、亮点 1：把「不展开数组」从要求书的例子里反推出来

要求书 2.3 给了一对**结构等价**的例子（域名不同：`{int x; float y;}` ≡
`{int y; float z;}`），又给了一对**不等价**的例子。后者初看令人费解：那两个结构体
「看起来挺像」，凭什么不等价？把最自然的那种实现 —— 结构等价＝把各域的类型**展开**
成一个序列再逐位比较 —— 代入就明白了：

```c
A = struct A { int a; struct { float f; int i; } b[10]; }  -> int, [float,int]x10  = 21 项
B = struct B { struct { int i; float f; } b[10]; int b; }  -> [int,float]x10, int  = 21 项
```

展开后 A 与 B **逐位完全相同**（`int==int`、`float==float`、…），于是会把要求书明确
判定为**不等价**的一对判成等价。所以那句话不是修辞，它是在说「别展开」：A 的第 0 个域
是 `int`、B 的第 0 个域是 `array`，**种类就已经不同**，立刻判出不等价。代码上它只是让
结构等价逐个比较域的类型，而数组域整体走 `typeEqual` 的数组分支（把整个数组当作一个
不可分割的（基类型, 维数）单位）。

值得注意的是，这对「不等价」的例子同时是「忽略域名」的独立佐证（它的两个结构体域名
正是不同的），而「忽略域名」的直接佐证又只能来自那对「等价」的例子。**推理到这里才
闭合**：两条规则互为对方的证据，任何一条单独看都像是凭空规定。

## 四、亮点 2：一个端到端**测不出来**的 bug，决定了模块边界

`int a[10][2]` 的 `VarDec` 树是左递归的：`VarDec(VarDec(a) LB 10 RB) LB 2 RB` ——
**最外层结点带的是最后一个方括号**。所以类型必须**从右往左**折叠；若照收集顺序从左
折叠，得到的是 `array(2, array(10, int))`：**维度顺序反了**。

这个 bug 在本实验里**没有任何症状**：数组等价**忽略长度**，反了的数组与任何同维数组
比较仍然「相等」；**维数没变**，于是错误 10（对非数组用 `[]`）的触发条件不变；错误 12
只看**下标**的类型，与数组本身是什么类型无关。也就是 17 种检查**一条都发现不了它**，
端到端用例全绿。

唯一能钉住它的办法，是让类型模块**脱离词法/语法/符号表独立单测**，并且断言**具体的
`size` 值**（只查维数同样抓不到）。`make type-test` 干的就是这件事。这就是这条模块边界
的由来：`type.c` **不依赖任何东西**（连符号表都不依赖），不是为了分层好看，而是因为
**只有它能看见这个 bug**。一句话：**判别力的边界决定模块的边界** —— 一个错误若在高层
没有任何可观测量，就只能靠把低层做成可独立测试的纯模块来发现。

## 五、亮点 3：把「要求书没规定」的十条做成可单点翻转的开关

要求书与指导书对十种情形**都没有写**：变量名与函数名冲突报哪个码？`if` 的条件不是
`int` 报错误 7 还是别的？形参与函数体算不算同一个作用域？`a[b]`（`b` 是数组）报 12
还是 7？同一行出现两条错误留哪一条？这些都是**推不出来的**，两份文档里都没有依据。

而实验二**有在线判分**：猜错的代价是当场丢分，且判分反馈通常只说「某个用例错」。所以
我们不猜，把它做成**可收敛的**。每条必须满足三点，缺一不可：

1. **行为收敛在代码里的一个位置**，并写明「这是第 N 条，要求书未规定」：
   `symtab.c` 的 `symConflictCode()`（1）、`semantic.c` 的 `checkCondition()`（2）、
   `analyzeExtDef` 的 `ED_FUNC` 分支里**那一次** `scopeEnter()` 调用 —— 它必须落在
   登记函数名**之后**、登记形参**之前**（3）、`analyzeStructSpecifier` 里定义结构体
   那条路径上的 `symEnter()` —— 用的是**当前**作用域深度、不开特例（4）、
   `analyzeStructSpecifier` 里 `nchild == 2` 的那个 `StructSpecifier : STRUCT Tag`
   分支（5）、`analyzeSubscript`（6）、`symEnter` 的返回值语义（7）、`checkable()`
   毒化开关（8）、`report.c` 的同行去重（9）、`type.c` 的 `structEquivalence`
   （选做 2.3）。做不到这一点，它就会退化成散在代码里的偶然行为，改一条要通读全文。
2. **各配一个专属用例**钉住当前行为（`Test/lab2/dec01`–`dec17`），且自检脚本断言这些
   用例**必须存在** —— 否则改错一条决策不会有任何用例变红。
3. **一张从症状反查决策的对照表**：

| 观测到的症状 | 最可能的决策 |
|---|---|
| 未定义变量的表达式被多报了一条类型错 | 8（`UNKNOWN` 毒化） |
| 同一行出现两条错误 | 9（同行只留最先检出的） |
| 某个跨函数的同名局部变量被报重复定义 | 3 或 4（作用域划在哪一层） |
| `if (3.7)` 被报错 / 该报错却没报 | 2（条件必须是 `int`） |
| 数组下标里放了个数组，报的码是 7 而不是 12 | 6（专项优先于通则） |
| 结构体与变量同名时报的码不对 | 1（单一名字空间，按后定义者报码） |
| 重复定义的变量，后续引用被解析到了后一个 | 7（保留最早那个） |
| `struct Undefined;`（无变量）没报 17 | 5（无变量也报） |
| 使用了文件后面才定义的变量/函数 | 10（定义必须先于使用） |

第 10 条要单独说：它的「开关」不是一行代码，而是**遍历结构本身**（单遍、不做预扫描），
也是十条里唯一「判分若指向它、修复成本不对称」的一条（要改成一趟预扫描先收集全局名），
所以它最需要这张表和那条用例。这张表才是整套做法的价值所在：判分反馈进来时（它只会说
「某个用例错了」），它是**唯一能立刻定位到是哪条决策**的东西。把未知收敛成已知，靠的
不是猜得准，而是**猜错时可查、可改、可验证**。

同一套思路也用在判分本身：每个官方样例配两个期望文件 —— `.exp` 钉我们自己的完整文本、
`.pairs` 钉官方的「错误类型 + 行号」序列（要求书明说这是唯一评分标准），两者分开才能
把「改了说明文字」与「错误类型/行号错了」分开暴露。最后一句方法论：本项目对**每一条
判据**都做了变异测试 —— 把它改坏，必须有用例变红；据此发现并修复了「判据看似存在、
实则没有判别力」的问题。举两个有名字的例子（取证都记在过程文档里）：Task 4 的
`scopeExit()` 摘链**当时没有任何断言看着** —— brief 原有的检查点全在
`scopeExit()` 之后、此时 `curDepth == 0`，`symLookup` 的深度守卫自己就把残留过滤掉了，
于是「退层不摘散列链」这个变异在用例下**存活**（补测后才杀死，见
`.superpowers/sdd/task-4-report.md`）；Task 8 的毒化探针**两个候选错误全部落在同一行**
（写成 `i = j + 1;`），被同行去重抑制，把毒化整个关掉也不变红 —— 必须把两个候选拆到
不同行（`i = 1` 换行 `+ j;`）才恢复判别力（见 `.superpowers/sdd/task-8-report.md`）。
